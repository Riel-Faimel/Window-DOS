# Window-DOS Kernel

> 在保护模式/长模式下，重现 DOS 系统调用的语义。

## 概述

Window-DOS 是一个面向 x86/x86_64 架构的操作系统内核。它在现代处理器的保护模式（32位）或长模式（64位）下，提供与经典 DOS 系统调用完全等价的语义接口，使开发者能够以熟悉的 `INT 21h` 风格访问硬件资源，却享受现代 CPU 的内存保护和异常处理机制。

内核采用模块化微内核设计，本体仅包含最基础的启动引导与命名空间解析逻辑，所有驱动程序均运行在 Ring 0，并通过两套独立的命名空间暴露系统资源。

## 设计哲学

- **兼容的语义** —— DOS 调用习惯不变，底层已是保护/长模式。
- **流/簇设备抽象** —— 一切皆设备，两套接口，两套抽象。
- **用户自由** —— 分页与抢占并非强制，由使用者决定开启与否。

## 核心架构

### 资源命名空间

系统将所有资源组织为两类设备空间，分别对应不同的系统调用接口：

| 命名空间 | 访问方式 | 示例 | 用途 |
|---------|---------|------|------|
| **流设备空间** | `\\name` | `\\com1`, `\\lpt1` | 流设备（串口、终端、管道） |
| **簇设备空间** | `name:` | `a:`, `c:`, `ram:` | 簇设备（磁盘、RAM 盘、文件系统卷） |

两套空间拥有各自独立的系统调用入口，以实现语义上的清晰分离。

### 驱动模型

- 所有驱动运行在 **Ring 0**，拥有完整的 I/O 权限。
- 驱动以独立模块形式存在，动态加载。
- 内核本体仅内置引导所必需的最小驱动集（如磁盘读取、基础显示），其余驱动在启动过程中按需加载。
- src/include/interface/ 下可见驱动接口

### 执行模式

- **保护模式 (32-bit)** + **长模式 (64-bit)** 扩展。
- **分页（Paging）** 与 **抢占式调度（Preemption）** 均为可选特性，可在构建时或启动时配置，以适应不同场景（嵌入式、实时、传统 DOS 替代等）。

### 技术栈

- **语言**：C++, NASM
- **构建工具**：Make
- **目标格式**：纯二进制（RAW binary）

### 构建

```cmd
mingw32-make clean
mingw32-make module_32
mingw32-make result
```
